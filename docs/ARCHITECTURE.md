# システム設計仕様書 (Architecture & Design)

## 1. 概要 (Overview)

本システム「MM-Workbench」は、非対称情報ゲーム（マーダーミステリー、TRPGシナリオ等）のプロット設計、論理検証、およびハンドアウト（HO）執筆を支援するAI共創型Webアプリケーションである。

従来のフォーム入力中心の静的CMSとは異なり、以下の課題を解決することを目的とする：
- **思考・共創プロセスの支援**: 単純なテキスト保存ではなく、AIとの対話を通じたキャラクター造形や動機の深掘り。
- **情報構造の可視化**: 「客観的証拠」と「プレイヤーの専門知識」が交差する情報ネットワークの設計。
- **演繹的ロジック検証**: 犯人特定の二重・三重ロックが論理的に破綻せず一意に特定できるかの整合性チェック。

---

## 2. コアアーキテクチャ

システムは大きく以下の4つのモジュールで構成される。

```
+-----------------------------------------------------------------------+
|                              MM-Workbench                             |
+-----------------------------------+-----------------------------------+
|       AI Co-Writer Engine         |      Information & Logic Matrix   |
|  - ペルソナ別壁打ちチャット       |  - 情報トランプ（公開事実×知識）  |
|  - キャラクター動機・ドラマ生成   |  - 多重ロック整合性検証器         |
|  - HO代筆・推敲・口調調整         |  - リソース消費・フェーズフロー   |
+-----------------------------------+-----------------------------------+
|                        Data & Export Layer                            |
|  - ローカルJSON永続化 / エクスポート (Markdown / テストプレイ用)      |
+-----------------------------------------------------------------------+
```

### 2.1 AI Co-Writer Engine（対話型共創エンジン）
- **役割**: 作者の思考パートナーとして、ブレスト、矛盾指摘、文章整形を担当。
- **コンテキスト同期**: ユーザーが定義した世界観ルール、レギュレーション、キャラクター属性を常にシステムプロンプトに動的注入し、文脈の一貫性を保つ。
- **ペルソナ切り替え**:
  - `Logic Checker`: 客観的視点から、証拠の抜け穴やミスリードの過不足を指摘。
  - `Drama Director`: キャラクターの自負、後ろめたさ、喪失体験を提案し、内面の葛藤を強化。
  - `Script Editor`: 口調や世界観に合わせたハンドアウト本文の清書・ブラッシュアップ。

### 2.2 情報トランプ（Information Matrix）モデル
証拠が全体公開されるレギュレーションにおいて、情報の価値は「事実の隠蔽」ではなく「知識による解釈の差分」によって生じる。

- **客観的事実 ($Fact$):** 全員が入手・閲覧可能な現場証拠や記録。
- **解釈知識 ($Knowledge_i$):** PC $i$ のみが持つ専門知識や個人的見聞。
- **導出結論 ($Conclusion$):** $Fact \cap Knowledge_i \rightarrow Conclusion$

本システムでは、この結びつきを行列（マトリクス）として管理し、特定PCへの情報偏重や、誰かが欠けた場合のデッドロックを検出可能にする。

### 2.3 多重ロック整合性検証器 (Multi-Lock Validator)
犯人特定に至る論理を複数の独立した条件軸（ロック）に分解し、真犯人ただ1名のみがすべての条件を満たし、他の容疑者全員に少なくとも1つの反証（アリバイ、物理的矛盾、動機の欠如など）が存在することをマトリクス上で照合・可視化する。

- ロック軸例:
  - 実行可能性（場所・時間・手段）
  - 動機・関与の元凶（因縁・渡航歴・利害）
  - 特殊ルールの制約（魔術的制約、専門技術、アイテム所持など）

## 3. UI/UX 設計指針

1. **Split-Screen Workbench（2ペイン構成）**:
   - **左ペイン**: AI Co-Writer（対話・壁打ち・プロンプトテンプレート）
   - **右ペイン**: キャンバス（HOエディタ、情報マトリクス、ロック検証ビュー）
   - チャットでの議論結果を、1クリックで右側のデータスロット（キャラクター設定やHO）へ反映可能。
2. **BYOK (Bring Your Own Key)**:
   - ユーザー自身の API Key（Google Gemini API）を利用し、クライアントサイド/セッション内でのみ保持。外部サーバーに秘密情報を送出しない。
3. **ローカルファースト & ポータブル**:
   - 設定データはローカルストレージおよびJSONファイルとしてエクスポート可能。

## 4. 技術選定

- **Frontend & Server**: Next.js 14+ (App Router, TypeScript, React 18+)
- **Styling**: Tailwind CSS, Lucide React (Icons)
- **Containerization**: Docker, Docker Compose
- **AI Integration**: Google Gen AI SDK (`@google/genai` or Gemini REST API)
