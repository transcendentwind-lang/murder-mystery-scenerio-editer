# 利用ガイド

確認日: 2026-11-09。現在の画面とソースに基づく手順。未実装機能は[PRODUCT_VISION.md](PRODUCT_VISION.md)を参照。

## 使う人と画面

| 利用者 | 主な作業 | 使う場所 |
|---|---|---|
| 作者 | 作品、人物、証拠、進行の編集、配布物の準備 | ローカルアプリの制作・資料・出力タブ |
| GM | 進行確認、証拠配布の判断、時間管理 | GM進行タブ、印刷したGM資料 |
| 参加者 | 対応作品の音響操作 | GMから案内された参加者専用画面 |

作者・GM画面には真相や個別情報を含む。参加者に見せる資料とGM用資料は、配布前に内容を確認する。

## 1. 作品を選ぶ・作る

起動はAIが担当する。起動後に [http://localhost:3000](http://localhost:3000) を開くと作品管理画面が表示される。後から開く場合は上部の「シナリオ切替・新規作成」を使う。

新しい作品は「新規作成」で題名、人数、GMの有無、世界観、目指す体験を入力する。人物・証拠・進行のひな型が作られるため、初期文面を作品に合わせて置き換える。既存作品の複製、JSONの読込・書出しも作品管理画面で行う。

組み込み作品はコード側の内容と同期するため、自由編集の原本として使う場合は[保存とバックアップ](#保存とバックアップ)を先に確認する。複製しても専用の進行画面まで同じ動作になる保証はない。専用処理が作品IDに結び付いているためである。

## 2. 人物と証拠を配置する

「② 登場人物…」タブでプロフィール、記憶、内面、HO本文を編集し、証拠の内容・取得者・入手フェーズ・公開区分を決める。

新規作品には、次の設計用画面がある。

- **情報トランプ**: 証拠と人物を結び付け、その人物の知識と導出結論を記入する。
- **多重ロック**: 条件を追加し、人物ごとの○×と反証理由を入力する。全条件に該当する人数を確認する。

「1人に収束」という表示は入力済みの○×の集計結果。証拠本文から犯人を推理した結果ではない。知識を持つ人物が不在でも解けるか、反証が本文で成立するかは作者が別に点検する。組み込みの協力型作品では、この2画面を表示しない。

## 3. 進行と情報開示を決める

「① フェーズ進行 ＆ タイムライン」でフェーズを選び、状況、全体議論、個別行動、開示証拠を整理する。組み込み作品では専用のタイムラインと図を利用する。

新規作品の「リソース／カウントダウン状態」は文章の記入欄。残数の自動計算や消費履歴の記録はない。フェーズを切り替えても、別端末の参加者画面へ自動配信されるわけではない。

## 4. 配布資料を確認して印刷する

「④ デザイン資料作成・編集」でHO、証拠、図・写真、GM資料のプレビューを選び、対象の印刷ボタンを使う。ブラウザの印刷画面で、用紙や向き、対象ページを確認し、紙への印刷またはPDF保存を選ぶ。

- HOにはB5の印刷機能がある。カードや図、GM資料にはA4の印刷機能がある。
- 対応カードには表紙ページ・内容ページをまとめた両面印刷用の出力がある。長辺とじを前提とした配置のため、印刷プレビューと試し刷りで表裏の対応を確認する。
- 資料画面の本文直接編集は現在無効。人物や証拠の本文は「② 登場人物…」で編集する。画面内の「推敲」はAI回答に接続されていない。
- 新規作品でも、既定の図・写真、専用カード、GM進行資料に組み込み作品向け内容が表示される箇所がある。別作品の資料として、そのまま一括配布しない。

表示上の装飾や保存表示だけで、編集内容の保持や印刷結果を保証しない。特に組み込み作品の保存制約を確認する。

## 5. 企画・台本を書き出す

「⑤ 企画書・一括台本」で企画概要を編集し、概要、HO全集、完全台本のコピー・保存・印刷を行う。文章ファイルは共有・確認用、JSONは作品データの退避・読込用として使い分ける。

台本生成には組み込み作品向けの見出しや定型文が残る。新規作品の出力は、本文だけでなく人数表記、進行、専用演出も確認する。

## 6. 当日進行する

「③ GM進行」でフェーズ別の状況・証拠・進行メモを確認し、タイマーを操作する。組み込み作品は専用の進行支援、新規作品は汎用のフェーズ進行画面となる。タイマーや当日の操作状態を、再読込で復元できる前提にはしない。

参加者用の独立画面は対応する組み込み作品専用。GMから渡されたURLで開き、音量と音の再生を確認する。作者側で選択した作品やフェーズと自動同期しない。アプリ内の音響タブと、独立した参加者画面では参照データが異なる。

## 保存とバックアップ

### 新規作品

編集は利用中のブラウザ内へ自動保存する。別のブラウザ、別端末、別の接続先には自動で移らない。ブラウザのデータ削除で失われるため、作業の区切りで作品管理からJSONを書き出す。

JSONを読み込むと新しいIDの作品として追加される。既存作品の上書き復元ではない。読込直後は現在の画面にデータを渡すため、不足項目の多い旧形式ファイルについては、正常表示や完全な互換性を保証しない。

### 組み込み作品

| 編集対象 | 現在の扱い |
|---|---|
| 人物・HO本文、作品概要、証拠一覧、進行概要、図版、専用カードなど | 再読込時にコード側の内容で再設定される |
| 既存証拠の題名・本文など | 保存時にもコード側の内容へ合わせられる |
| 情報トランプ・多重ロックのデータ | 保存・読込処理で除去される |

組み込み作品の編集については、画面の変更や保存表示だけで次回も残ると判断しない。保持したい場合は、再読込前にJSONを書き出し、新しい作品として読み込んで内容を確認する。書き出す時点の画面データが対象となり、既にコード側へ戻った編集は復元できない。

この保存挙動は現状の制約。編集原本と組み込みデータの関係を改善する課題として[目指す体験](PRODUCT_VISION.md)に記録している。
